# Промт для Claude Code. Прототип интернет-магазина Zümrüd Parfum

Скопируй всё, что ниже строки, и вставь в Claude Code.

## ЗАДАЧА

Построй рабочий прототип интернет-магазина парфюмерии Zümrüd Parfum (Баку, район Насими).
Это демонстрация для владельца магазина, её откроют с телефона. Не продакшн.
Цель прототипа показать, как выглядит и работает покупка, а не держать реальные заказы.

## СТЕК

Next.js (App Router), TypeScript, Tailwind CSS.
Без бэкенда, без базы данных, без API-роутов для заказов.
Все товары лежат в одном файле данных `src/data/products.ts`.
Корзина в localStorage, состояние через React Context.
Деплой на Vercel. Репозиторий [ССЫЛКА].

## ЯЗЫКИ

Азербайджанский по умолчанию, русский вторым.
Все строки интерфейса в словарях `src/i18n/az.ts` и `src/i18n/ru.ts`. Ни одной зашитой строки в компонентах.
Выбранный язык хранится в localStorage, переключатель в шапке.
Полная диакритика, проверь что ə ş ç ğ ı ö ü İ Ə Ş Ç Ğ Ö Ü рендерятся везде, включая шрифт заголовков.
Названия товаров остаются латиницей в обоих языках, переводятся только интерфейс, категории, пол, описания нот.

## ФОТОГРАФИИ ТОВАРОВ. ОТДЕЛЬНЫЙ ВАЖНЫЙ БЛОК

Заглушек быть не должно. Скачай настоящие фотографии сам.

1. Для каждой позиции ищи официальное изображение флакона по точному запросу бренд плюс название плюс объём.
2. Источники в порядке приоритета. Сайт самого бренда (lattafa.com, rasasi.com, afnanperfumes.com, armafperfumes.com, fragranceworld.ae и аналогичные). Крупные официальные дистрибьюторы. Wikimedia Commons.
3. Запрещено брать фотографии с сайтов других бакинских магазинов парфюмерии и запрещено брать кадры из инстаграма Zümrüd. Там водяные знаки и чужая съёмка.
4. Клади файлы в `public/products/`, имя файла по слагу товара, например `public/products/rasasi-hawas-ice.webp`.
5. Приводи к одному размеру. Квадрат 800 на 800, формат webp, фон белый или прозрачный, флакон вписан с полями.
6. После загрузки проверь каждый файл скриптом, а не глазами. Напиши `scripts/check-images.mjs`, который для каждого файла проверяет
   - файл существует и открывается как изображение (через sharp или image-size)
   - размер ровно 800 на 800
   - вес больше 5 килобайт
   - это не HTML-страница ошибки, не логотип сайта, не баннер. Отсеивай по пропорциям исходника до ресайза, по среднему цвету (сплошная заливка почти на всю площадь это баннер) и по тому, что в кадре есть тёмный объект на светлом фоне
   - выводит таблицу `slug, ok/fail, причина`
7. Для позиций, где ничего чистого не нашлось, сгенерируй аккуратную заглушку. Однотонная плитка 800 на 800 в фирменных цветах, по центру название бренда капителью золотом на тёмно-зелёном. Генерируй скриптом, не руками.
8. Положи рядом `public/products/sources.json` с записями вида `{ "slug": "...", "url": "...", "type": "brand-site | wikimedia | placeholder" }`, чтобы потом можно было заменить.
9. В конце выведи отчёт. Сколько фотографий нашлось, для каких позиций стоит заглушка, какие ссылки не прошли проверку и почему.

Запуск `node scripts/check-images.mjs` должен завершаться без единого fail до того, как ты скажешь, что готово.

Сортировка. По популярности (порядок в файле), цена по возрастанию, цена по убыванию, название А-Я.
На телефоне фильтры в нижней шторке, кнопка Filtrlər с числом активных фильтров, кнопка Təmizlə.
Фильтры пишутся в query string, чтобы ссылку можно было переслать.
Счётчик найденных товаров и внятное пустое состояние.

### Страница товара `/product/[slug]`
Галерея. Пока изображение одно, галерею делай готовой к нескольким.
Бренд ссылкой в каталог с фильтром по бренду.
Название, объём, концентрация, пол.
Цена крупно.
Кнопка Səbətə at, после нажатия короткое подтверждение и возможность перейти в корзину.
Пирамида нот тремя группами, Yuxarı notlar, Orta notlar, Baza notları. Если нот нет, блок скрыт.
Описание.

### Корзина `/cart`
Список позиций, картинка, бренд, название, объём, цена за штуку, изменение количества, удаление.
Итого.
Кнопка оформления.
Пустая корзина с кнопкой в каталог.
Корзина переживает перезагрузку страницы.

### Оформление `/checkout`
Ровно два шага.
Шаг 1. Имя, телефон, способ получения. Çatdırılma или Mağazadan götürmə. При доставке адрес и комментарий. При самовывозе выбор одной из двух точек.
Шаг 2. Проверка заказа, список позиций, итог, кнопка оплаты.
Валидация простая, телефон в формате +994 и девять цифр.

## ИМИТАЦИЯ ПОКУПКИ

Кнопка оплаты запускает задержку полторы секунды со спиннером, затем экран успеха `/checkout/success` с номером заказа вида `ZP-XXXXXX`, суммой и текстом, что это демонстрация и заказ никуда не отправлен.
Деньги не списываются, никаких платёжных форм и полей карты на экране нет.
В коде рядом с функцией имитации оставь комментарий.

```ts
// DEMO ONLY. Здесь в продакшне будет вызов платёжного шлюза epoint.az
// Сейчас оплата имитируется задержкой, никакие данные карты не собираются.
```

## КРИТЕРИИ ГОТОВНОСТИ

Проверяй сам, в браузере, на ширине 390 пикселей.

1. С телефона можно найти товар поиском или фильтром, открыть его, положить в корзину, изменить количество, дойти до оплаты и увидеть подтверждение с номером заказа.
2. Переключение языка меняет весь текст интерфейса, включая фильтры, кнопки, подвал, плашку демо и экран успеха. Непереведённых строк не остаётся.
3. Корзина переживает перезагрузку страницы и возврат назад.
4. Горизонтальной прокрутки нет ни на одной странице при 390 пикселях. Проверь скриптом, `document.documentElement.scrollWidth <= window.innerWidth` на каждом маршруте.
5. Все картинки товаров загружаются, битых нет. `node scripts/check-images.mjs` проходит без fail.
6. Плашка демо видна вверху каждой страницы, и при `SHOW_DEMO_BANNER = false` исчезает везде одним изменением.
7. `npm run build` проходит без ошибок и без предупреждений TypeScript.
8. Диакритика отображается корректно во всех шрифтах и размерах.
